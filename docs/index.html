Embedded SQL database

A one-file SQL database with full SQL:2023 support.

vsql follows the SQL standard, keeps everything in a single file or in memory, and runs as one binary written in pure V. No server, no setup, no surprises in production.

Features

Built like a database. Ships like a file.

Everything you expect from a server database, embedded in your program. Pick a capability below to see the SQL and the documentation behind it.

One dialect, wherever you run it

vsql targets the SQL:2023 standard instead of its own dialect. Queries, schema and skills carry over to PostgreSQL and other standard databases. Errors use standard SQLSTATE codes such as 23505 for a duplicate key.

  • Joins, subqueries and aggregates
  • Cursors, custom functions and prepared statements
  • Published compliance tables for every feature
SQL compliance tables
reports.sqlSQL
SELECT p.name, SUM(o.quantity) AS units
FROM orders o
JOIN products p ON p.name = o.product
GROUP BY p.name
HAVING SUM(o.quantity) > 10
ORDER BY units DESC;

Transactions you can rely on

SERIALIZABLE is the default, and all four standard isolation levels are available. MVCC lets readers and writers work at the same time, while a write-ahead log keeps the file safe after a crash or power failure.

  • Multiple connections in one process or across processes
  • Savepoints, rollback and crash recovery
  • Locks held per statement, not for the whole transaction
Transactions and isolation levels
transfer.sqlSQL
BEGIN TRANSACTION ISOLATION LEVEL SERIALIZABLE;
UPDATE accounts SET balance = balance - 100
  WHERE id = 1;
UPDATE accounts SET balance = balance + 100
  WHERE id = 2;
COMMIT;

Strict types, exact numbers

Putting text in an INTEGER column is an error instead of silent data loss. NUMERIC and DECIMAL stay exact, so money adds up to the cent, and DATE, TIME and TIMESTAMP support time zones.

  • Exact decimal arithmetic with controlled scale
  • Temporal types, with or without time zone
  • Standard SQLSTATE errors when a value does not fit
Numbers and exact types
invoices.sqlSQL
CREATE TABLE invoices (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  total NUMERIC(12, 2) NOT NULL,
  issued_on DATE NOT NULL,
  paid_at TIMESTAMP WITH TIME ZONE
);
SELECT SUM(total) FROM invoices;

Constraints and indexes

Enforce your rules in the database: primary keys, UNIQUE, FOREIGN KEY and CHECK constraints, plus sequences, identity columns and ALTER TABLE when the schema changes.

  • Deferrable constraints and referential integrity
  • Indexes, including multi-column indexes
  • ALTER TABLE adds and drops columns and constraints
Indexes and constraints
bookings.sqlSQL
CREATE TABLE bookings (
  id INTEGER PRIMARY KEY,
  room INTEGER NOT NULL REFERENCES rooms(id),
  seats INTEGER CHECK (seats > 0),
  UNIQUE (room, seats)
);
CREATE INDEX bookings_room ON bookings (room);

Inspect the database the standard way

The standard INFORMATION_SCHEMA views describe tables, columns, constraints and routines, so tools and migration code can discover your schema without database-specific pragmas.

  • Works with ordinary SELECT queries
  • No PRAGMA or vendor-specific system tables
  • EXPLAIN for query plans
INFORMATION_SCHEMA reference
columns.sqlSQL
SELECT table_name, column_name, data_type
FROM INFORMATION_SCHEMA.COLUMNS
WHERE table_name = 'PRODUCTS'
ORDER BY ordinal_position;

One file, or none at all

Copy, back up or email a database like any other file. Use :memory: when you need a database that only lives for the process.

Performance and confidence

Fast enough to test with. Safe enough to ship with.

On a 100,000-account database on an Apple M-series Mac, vsql runs about 1,350 TPC-B transactions per second and inserts about 9,000 rows per second while setting up the file. Run vsql bench to measure your own machine. Every line of the database must be covered by a test before a change is merged, on Linux, macOS and Windows across x86-64 and ARM64.

Why vsql

SQLite is easy. vsql behaves like a real SQL database.

Both are one file with no server. The difference shows up when your application relies on types, transactions or standard SQL.

A feature comparison based on the project README.
