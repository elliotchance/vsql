fn open_database
----------------


.. code-block:: v

   pub fn open_database(path string, options ConnectionOptions) !&Connection

open_database will open an existing database file or create a new file if the path does not exist.

If the file does exist, open_database will assume that the file is a valid database file (not corrupt). Otherwise unexpected behavior or even a crash may occur.

The special file name ":memory:" can be used to create an entirely in-memory database. This will be faster but all data will be lost when the connection is closed.

open_database can be used concurrently for reading and writing to the same file and provides the following default protections:

- Fine: Multiple processes open_database() the same file.

- Fine: Multiple goroutines sharing an open_database() on the same file.

- Bad: Multiple goroutines open_database() the same file.

See ConnectionOptions and default_connection_options().

An Agent is an SQL-agent, which runs <direct SQL statement>s on its SQL-connections, and is how "vsql cli" runs statements. Unlike a Connection, it can run the connection statements: CONNECT TO, SET CONNECTION and DISCONNECT. The SQL-connections that aren't current are dormant, and each keeps its own SQL-session context.

Each SQL-connection is to a different SQL-server (a database file, or a new in-memory database), and vsql doesn't support transactions that affect more than one SQL-server. So only the current SQL-connection can have an active SQL-transaction.

A prepared statement is compiled and validated, but not executed. It can then be executed with a value for each dynamic parameter ("?") in the statement, named by its position: "?1", "?2", etc. Each invocation requires all of them to be passed in.

A prepared statement isn't deallocated when an SQL-transaction ends, so it can still be executed after a COMMIT or ROLLBACK.

struct Sequence
---------------


.. code-block:: v

   pub struct Sequence {
   mut:
   	// The tid is the transaction ID that created this table.
   	tid u64
   	// exhausted is true when current_value is the last value that can be
   	// returned, because adding increment_by would go past the range of a BIGINT.
   	// See next.
   	exhausted bool
   	// unused is true when current_value plus increment_by (the current base
   	// value) hasn't been returned by NEXT VALUE FOR yet, which is a new sequence
   	// or one that has been restarted. Otherwise current_value is the last value
   	// that was returned. ALTER SEQUENCE needs to know which, see
   	// AlterSequenceGeneratorStatement.
   	unused bool
   pub mut:
   	// name contains the other parts such as the schema.
   	name Identifier
   	// start_value is the START WITH value. If START WITH isn't given, it's the
   	// minimum value (or the maximum value for a descending sequence), which is 1
   	// (or -1) without a MINVALUE (or MAXVALUE). It's used by "ALTER SEQUENCE ...
   	// RESTART".
   	start_value i64
   	// current_value is the current value before it is incremented by
   	// "NEXT VALUE FOR".
   	current_value i64
   	// increment_by is added for each next value and defaults to 1.
   	increment_by i64
   	// cycle allows the sequence to repeat once MAXVALUE is reached. By default it
   	// is not enabled.
   	cycle bool
   	// has_min_value is true when a MINVALUE is set. Otherwise, the minimum
   	// value is implicit, see min.
   	has_min_value bool
   	// min_value is the smallest inclusive value allowed for the sequence. The
   	// MINVALUE is optional.
   	min_value i64
   	// has_max_value is true when a MAXVALUE is set. Otherwise, the maximum
   	// value is implicit, see max.
   	has_max_value bool
   	// max_value is the largest inclusive value allowed for the sequence. The
   	// MAXVALUE is optional.
   	max_value i64
   }

A SEQUENCE definition, which is the sequence generator descriptor. The data type is always BIGINT (#399). The current base value is current_value plus increment_by when the sequence is unused, otherwise the next value after current_value.
